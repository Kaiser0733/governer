Why the bill grows while you sleep

The prefix is replayed

Million-token contexts are table stakes, so the whole cached prefix goes back on every call. Cache reads dominate an agent bill — and they are billed even when that text is truncated before the model reads it.

“Caching supported” is not caching

Every layer in the chain can assume prompt caching works while the actual agent stack misses it. Nothing in the stack reports that. One documented case: $37,901.73, of which $35.6k was uncached input.

Alerts are not limits

Email after the money is gone is not a safety mechanism. Neither are credits, nor a dashboard you check on Mondays. The only control that holds at 4am is a refusal.

Commands

governer proxy --limit 5OpenAI-compatible shim; refuses past $5, passes your own key through
governer check usage.json --limit 20true cost of a log, and where a $20 cap would have stopped it
governer boxsimulated agent in a virtual wallet, no API key
governer prices --upcomingannounced price changes
governer verify spend.jsonlis the ledger intact

Per-agent and per-day caps via X-Governer-Agent. --dry-run books the real spend and refuses nothing, so you can watch before you enforce.
